# Prototype

State the uncertainty the prototype should resolve, its time/effort bound and the
observation that will end it. Start with one approach. Compare another only when a
real decision depends on that comparison and the budget permits it.

Build enough of the user path to collect the observation. Prefer disposable data
and fixtures. Record what was learned, reusable parts and shortcuts that prevent
production use. Prototype success means the question was answered; it does not
mean the artifact is production ready. Keep verification proportional to that
decision while running any required checks.
