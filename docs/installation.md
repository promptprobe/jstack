# Installation, updates and removal

## Skill-only: download, copy, invoke

Download [jstack-mode.zip](https://github.com/promptprobe/jstack/releases/download/v0.2.0/jstack-mode.zip)
and extract it. Copy the entire `jstack-mode` folder to **one scope per host**:

| Host | Personal | Project |
| --- | --- | --- |
| Codex | `~/.agents/skills/jstack-mode/` | `.agents/skills/jstack-mode/` |
| Claude Code | `~/.claude/skills/jstack-mode/` | `.claude/skills/jstack-mode/` |

Create missing directories. The result must be `.../skills/jstack-mode/SKILL.md`,
not a second nested `jstack-mode` folder. The `references/` directory is required.
The same ZIP supports both hosts. Invoke `$jstack-mode normal` in Codex or
`/jstack-mode normal` in Claude Code. Refresh/restart the host if it is not listed.

No Python, Git clone, helper setup, config file or changes to AGENTS.md/CLAUDE.md
are required. Your project still needs its own dependencies to execute tests.
The active flag and budget live in conversation context. `jstack off` clears that
mode in the current conversation; a new conversation requires a new invocation.
Checks use existing host tools and report results in conversation. Retry budgets
are agent instructions; no CLI receipts or automated fingerprints are claimed.

An existing `.jstack/config.json` can supply budget, agent preferences and checks.
It does not automatically select recorded operation. Absent config uses `normal`,
fanout off, and project-discovered checks. No config is generated by activation.

For updates, preserve any edited skill elsewhere, remove the old **skill folder**,
and copy the new one into the same location. For removal, delete the copied
folder; no other jstack files were installed. Project copies can be committed for
team use. Personal copies apply to that user's projects only.

## Optional recorded operation

Only install this if you want persisted contracts, command receipts, per-task
retry enforcement and Git-visible source fingerprints. You need Python 3.10+
and Git, with the target at a Git repository root.

```sh
git clone https://github.com/promptprobe/jstack.git "$HOME/.local/share/jstack"
cd /path/to/your/project
python3 "$HOME/.local/share/jstack/jstack.py" setup --host both --dry-run
python3 "$HOME/.local/share/jstack/jstack.py" setup --host both
```

Choose `--host codex` or `--host claude` for one host. Use `--project /absolute/path`
if needed. If a manually copied **project skill** already occupies the target,
move it to a backup outside the discovery directory first: setup deliberately
refuses unowned files. Also avoid keeping the same skill in personal and project
scope. Do not erase edited files just to bypass a conflict.

Setup copies the runtime and replaces `references/host.md` with a host adapter.
Configure real commands in `.jstack/config.json` using [configuration](configuration.md)
and [examples](../examples). Then run `python3 .jstack/jstack.py doctor`.
An empty check list cannot pass. Checks execute project code; inspect them first.
The installed runtime does not need the source checkout after setup.

Invoke the skill and explicitly request **“Use jstack recorded mode”**. Even with
the runner installed, ordinary invocation defaults to skill-only operation.
Recorded mode keeps an explicit session ID in conversation. Installation and
`doctor` do not prove model behavior or actual host discovery.

### Files and ownership

| Path | Ownership |
| --- | --- |
| `.jstack/config.json` | User/team; setup creates only if absent |
| `.jstack/jstack.py`, `.jstack/jstack_core/` | Managed runtime |
| `.agents/skills/jstack-mode/` | Managed Codex skill files; extra user files preserved |
| `.claude/skills/jstack-mode/` | Managed Claude Code skill files; extra user files preserved |
| `AGENTS.md`, `CLAUDE.md` | Only the marked jstack block is managed |
| `.gitignore` | A marked privacy block is added; other content preserved |
| `.jstack/install.json` | Managed file hashes, host list and instruction-block hashes |
| `.jstack/local/` | Private local sessions, tasks, runs and observations |

Setup preflights conflicts before writing. It rejects symlinked managed paths,
unowned collisions, changed/missing owned files and malformed instruction markers.
No force overwrite is offered. Preserve edits and resolve the specific conflict.
Ordinary write failures roll back; abrupt termination or power loss is not
transactional. Inspect partial state or restore from Git after such interruption.

`--dry-run` writes nothing. Regular mutations share an exclusive project lock;
a second writer exits. After a crash, confirm no jstack process is running before
removing `.jstack/write.lock`. Sessions isolate records, not application edits;
use separate worktrees when application changes may collide.

### Update the optional runner

```sh
git -C /path/to/jstack pull --ff-only
python3 /path/to/jstack/jstack.py setup --project /path/to/project --host both
```

Unchanged installations are idempotent. Config and records survive updates.
Locally modified owned files stop the update. Review and commit the installed
skill, runtime, config and manifest as appropriate. Keep `.jstack/local/` ignored:
it can contain private task text and command output. No automatic download occurs.

### Remove the optional runner

```sh
python3 .jstack/jstack.py uninstall --dry-run
python3 .jstack/jstack.py uninstall
```

This removes owned runtime/skills and instruction blocks, preserving config,
records, user-added files and the privacy ignore block. A small manifest permits
reinstallation. To return to skill-only use, copy the portable skill folder after
uninstalling. Review retained records before deleting or sharing them.

## Host compatibility

Discovery paths follow [OpenAI's skills documentation](https://learn.chatgpt.com/docs/build-skills)
and [Claude Code's skills documentation](https://code.claude.com/docs/en/skills).
Organization policy can restrict discovery. Host behavior still depends on its
version, model and permissions. No hooks, MCP servers or global settings are added.

## Build a distributable skill (maintainers only)

```sh
python3 scripts/build_skill.py
```

This produces `dist/jstack-mode.zip` and `dist/SHA256SUMS`. Only skill files and the
MIT license are included. Local references must resolve inside the skill; missing
references, symlinks and unexpected file types fail packaging. ZIP metadata is
fixed for repeatable builds within the same compression environment. Checksums
are unsigned integrity checks, not publisher identity verification. Consumers do
not need Python or this builder to unpack and use the release asset.
