# 실제 동작 검증 기록

검증일: 2026-09-16, 미국 로스앤젤레스 시간 기준.

**Codex에서 작은 테스트 프로젝트를 대상으로 실제 3턴 작업이 동작하는 것을 확인했습니다. 신뢰도: 높음(high).** 설치 파일만 검사한 결과와 모델이 실제 수행한 결과를 구분합니다.

## 검증 환경

- jstack 실행 코드: `5a33920c17afe0dc4f809540f24c1101bffc321a`
- Codex CLI: `0.154.0`
- 모델: `gpt-6-astra`, 기존 호스트 추론 설정: `max`
- jstack 작업 강도: `cheap`
- 대상: 별도의 장바구니 테스트 프로젝트. 외부 서비스나 실제 운영 데이터 사용 없음.
- Claude Code: 현재 환경에 CLI가 없어 실제 모델 실행은 검증하지 못함.

기존 CLI `0.149.1`에서는 모델 버전 호환 오류가 발생했습니다. jstack이 실행되기 전 발생한 환경 문제입니다. 공식 배포본의 CLI와 동일 버전 실행 구성요소를 작업 폴더에만 받아 해시를 확인한 뒤 사용했습니다. 기존 전역 설치·설정·모델은 변경하지 않았습니다.

## 실제로 사용한 요청

첫 번째 턴:

```text
$jstack-mode cheap
장바구니에서 같은 상품을 다시 추가하면 기존 수량이 사라지는 버그를 고쳐줘.
기존 입력 딕셔너리는 바뀌면 안 돼.
필요한 검증까지 하고 결과를 한국어로 알려줘.
```

같은 대화의 두 번째 턴에서는 스킬 이름과 작업 강도를 다시 쓰지 않았습니다.

```text
추가로, 수량이 0이면 기존 장바구니와 같은 값만 반환하고
없는 상품을 새로 만들지 않도록 해줘. 기존 입력도 바뀌면 안 돼.
테스트와 필요한 검증까지 해줘.
```

세 번째 턴:

```text
jstack off. 이제 README의 한 줄 설명을
"A small immutable shopping cart example."로 바꿔줘.
```

두 번째 턴은 실제 Codex 대화를 재개해서 실행했습니다. 하나의 프롬프트에 가상 대화를 넣어 흉내 낸 검사가 아닙니다. 결과 판정도 모델의 최종 답변만 보지 않고 작업·세션·실행 기록과 수정된 파일을 확인했습니다.

## 직접 재현하기

[의도적으로 버그를 넣은 테스트 예제](../examples/cart-host-eval)를 별도 폴더로 복사합니다. jstack 저장소의 최상위 폴더에서 다음과 같이 준비할 수 있습니다.

```sh
JSTACK_EVAL_DIR="$(mktemp -d)"
cp -R examples/cart-host-eval/. "$JSTACK_EVAL_DIR/"
git -C "$JSTACK_EVAL_DIR" init
python3 jstack.py setup --project "$JSTACK_EVAL_DIR" --host codex
cp examples/python.json "$JSTACK_EVAL_DIR/.jstack/config.json"
codex -C "$JSTACK_EVAL_DIR"
```

같은 대화에 위 요청을 한 턴씩 입력합니다. 실제 모델 사용량이 발생하는 수동 평가이며, 기본 CI에서 실행하지 않습니다. Python과 Git을 사용할 수 있어야 하고, Codex 버전이 선택한 모델을 지원해야 합니다. Claude Code로 반복하려면 `--host claude`로 설치한 뒤 해당 폴더에서 Claude Code를 열고 `/jstack-mode`로 시작하세요. 그 결과는 이 문서의 Codex 관찰 결과와 별도로 판정해야 합니다.

`.jstack/local/` 아래 세션·작업·실행 JSON으로 같은 세션 유지 여부와 실패/성공 기록을 확인할 수 있습니다. 모드 해제 전후에는 작업·실행 파일 수가 늘지 않았는지도 비교하세요. 검증 후 README를 바꾸면 기존 소스 식별값이 달라져 과거 보고서가 오래된 결과로 표시되는 것이 정상입니다.

## 이 결과로 알 수 없는 것

한 개의 작은 예제와 한 가지 모델 설정에서 확인한 결과입니다. 대규모 저장소, 긴 대화, 강제 문맥 요약, 다른 모델에서 같은 수준의 지침 준수가 반복되는지는 추가 검증이 필요합니다.

특히 **`cheap`이 호스트의 `max` 추론 설정을 낮추지는 않았습니다.** 탐색·재시도·하위 에이전트의 작업 규칙과 실제 모델 비용은 구분해야 합니다. 이 검증은 비용 절감 벤치마크가 아닙니다.
